# Publishing Dejavu on F-Droid

F-Droid compiles every app itself, from public source, and ships only what came out of that compile.
This guide is how Dejavu is built there, and the steps to repeat for every release.

| Where | What it is |
| --- | --- |
| `fdroid/com.byarchitect.dejavu.yml` | A copy of the recipe in the fdroiddata merge request |
| <https://gitlab.com/by-architect/dejavubuild> | The build repository F-Droid builds from: a fork of Fennec F-Droid's fennecbuild, plus Dejavu's patch |
| `scripts/dejavu-fdroid-patch.sh` (in the project folder) | Writes Dejavu's patch, pictures and store listing into dejavubuild |

The store listing lives in `fastlane/metadata/android/` here, generated by `scripts/dejavu-fastlane.sh` in the
project folder, and is copied into dejavubuild with the patch.

- `prebuild.sh` runs through on the 159 source.
- F-Droid's scanner finds nothing in dejavubuild, so the recipe has no `scanignore`.

- The release build's dependencies (`:fenix:dependencies`) include no Google Play services, Firebase, ML Kit,

size: Fennec's update requests have theirs stopped and are merged anyway.

## How it is built

[fennecbuild](https://gitlab.com/relan/fennecbuild) holds no browser code, only `prebuild.sh`, `build.sh`, patches and
the store listing. F-Droid checks out Firefox's release source as a srclib (`MozFennec@FIREFOX-ANDROID_<version>_RELEASE`
from <https://github.com/mozilla-firefox/firefox>), and Application Services, Glean, WASI SDK and LLVM as srclibs
too, and compiles all of it. Srclibs are not scanned the way the build repository is, so nothing needs `scanignore`.

dejavubuild adds three things to that:

- `dejavu.patch`, every text change Dejavu makes to the Firefox release, applied first;
- `dejavu-overlay/`, Dejavu's pictures, copied over the source;
- `dejavu-remove-push-firebase.patch`, which leaves the unused Firebase push component out of the Gradle build.

Dejavu already builds without Google's and Adjust's libraries, so fennecbuild's own liberation patches for Fenix,
Android Components and GeckoView, microG, UnifiedPush and Fennec's search engines are left out. dejavubuild's README
lists every patch and why it is kept or dropped.

`proprietary.gradle.off` and `src/proprietary/` stay out of the patch: only the Google Play build switches them on.

## Moving to the Firefox 159 release (from 2026-10-27)

1. **Move Dejavu onto Firefox 159.** This repository is shallow, so fetch the release with enough history to merge
   it: `git fetch --shallow-since=2026-09-24 upstream tag FIREFOX-ANDROID_159_0_RELEASE`. Merge it into `main`
   (merge, never rebase). A trial merge of 159.0b1 had two conflicts: the imports in `FenixApplication.kt` (keep
   both `ComponentCallbacks2` and `ComponentName`) and `.github/workflows/pr-handler.yml`, which Dejavu deleted and
   Mozilla changed (keep it deleted). Build, test on a phone, release (for example `v2.1.0`) and push the tag.
2. **Make the patch.** In the project folder:
   `scripts/dejavu-fdroid-patch.sh FIREFOX-ANDROID_159_0_RELEASE v2.1.0`
3. **Release dejavubuild.** Commit there, tag it `v2.1.0`, push the commit and the tag.
4. **Update the recipe.** Add a `Builds:` entry with `MozFennec@FIREFOX-ANDROID_159_0_RELEASE`, the new version and
   `commit: v2.1.0`, and update `CurrentVersion` and `CurrentVersionCode`. Run `fdroid lint com.byarchitect.dejavu`
   and send it to fdroiddata.

## Every release after that

1. Release Dejavu and push its tag.
2. Run `scripts/dejavu-fdroid-patch.sh FIREFOX-ANDROID_<firefox version>_RELEASE v<dejavu version>`.
3. Commit and tag dejavubuild with the same version, and push.
4. Add a `Builds:` entry to the recipe and update `CurrentVersion` and `CurrentVersionCode`, in a merge request to
   fdroiddata.

## A new Firefox version

1. Merge the Firefox release into Dejavu, release Dejavu.
2. Bring dejavubuild to that Firefox version: merge relan's fennecbuild update when there is one (keep dejavubuild's
   `fastlane/`, carry the new versions over), or update it the same way it was moved to 159: the srclib versions
   (the recipe's MaintainerNotes say where to find each), the Android SDK packages in `build.sh`, the NDK, and any of
   the kept fennecbuild patches that no longer apply.
3. Then the steps above.

## Lessons

- **CI formats YAML differently from a released fdroid.** CI uses fdroidserver master with Debian's ruamel.yaml,
  which wraps a long `output:` value onto its own line; fdroid 2.4.3 does not, so `fdroid rewritemeta` passes locally
  and fails in CI. Commit the wrapped form, with its trailing space, as `org.mozilla.fennec_fdroid.yml` does.
- **`UpdateCheckMode: Tags` cannot work.** `checkupdates` reads every AndroidManifest.xml it finds, and the Firefox
  tree has hundreds in tests, so it gives up. Fennec uses `None` for the same reason.
- **Building this repository directly does not pass the scanner.** It found 3,627 problems: Windows import libraries
  in `third_party/rust`, test binaries, WebAssembly and archives. That is what the srclib route avoids.
- **Firefox 159 wants exactly NDK r30** (`30.0.16248370`); configure stops on any other.
- **Glean and Application Services still want NDK r29** (`29.0.14206865`, their `ndkVersion`). With r30 alone Glean
  fails with "NDK is not installed". The recipe's `ndk:` takes one version only (fdroiddata's schema rejects a list,
  whatever the docs say), so it stays r30 and dejavubuild's `build.sh` installs r29 with `sdkmanager 'ndk;...'`.
- **GitLab keeps only 4 MB of a job's log** unless the runner's `output_limit` is raised; the LLVM and WASI SDK builds
  fill that, and the real error is lost. mjolnir's runner has `output_limit = 51200`.
- **Firefox 159's `build.gradle` has a second `include "..."`** (`include "**/*.kt"` for the SafeArgs workaround), so
  fennecbuild's ABI `sed` has to be limited to the line that lists the ABIs.
- **`mach bootstrap` does not run on NixOS** ("Bootstrap support for this Linux distro not yet available"). Local
  builds use the tools already in `~/.mozbuild`.
- **Anti-features.** A browser that can install add-ons from addons.mozilla.org must keep those downloads opt-in;
  Gecko Media Plugins, EME and OpenH264 are switched off by `prebuild.sh`, as in Fennec.
- **One CPU architecture.** arm64-v8a only. Each extra architecture needs its own `Builds:` entry and version code
  below 2100000000, so the version code scheme has to change before a second one is added.
